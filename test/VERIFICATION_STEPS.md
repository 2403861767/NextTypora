# BUG-P0-003 修复验证步骤

## 修复内容概述

修复了文件重命名/移动时，前端打开的标签页未同步路径导致保存失败的问题。

**改动文件**：
- `frontend/src/App.tsx`（约 70 行改动）

**新增功能**：
1. 检测保存时的 404 错误（文件已被移动/删除）
2. 标记受影响的标签页为 `missing` 状态
3. 弹出对话框提示用户文件已消失
4. 提供"另存为"和"关闭标签页"两个选项

---

## 详细验证步骤

### 前置条件
1. 确保后端和前端服务已启动：
   ```bash
   npm run dev:backend
   npm run dev:frontend
   ```
2. 在浏览器中打开 `http://localhost:5173`
3. 选择 `d:\project\NextTypora` 作为工作区

### 测试场景 1：文件重命名后保存

**步骤**：
1. 在应用中打开文件 `test/test.md`
2. 编辑文件内容，添加一些新文本（例如："这是测试内容 - 场景1"）
3. **不要等待自动保存**（800ms 延迟），立即进行下一步
4. 在 Windows 资源管理器中，导航到 `d:\project\NextTypora\test\`
5. 将 `test.md` 重命名为 `test-renamed.md`
6. 返回应用，点击文件树的刷新按钮（或按 `F5`）
7. 继续在编辑器中添加更多文本（例如："又添加了一些内容"）
8. 等待 1 秒，触发自动保存

**预期结果**：
- ✅ 弹出对话框："文件已被移动或删除"
- ✅ 对话框内容显示：文件 `test/test.md` 已被移动或删除
- ✅ 提供两个按钮：
  - "另存为"（确认按钮）
  - "关闭标签页"（取消按钮）
- ✅ 标签页上显示 `test.md` 带有错误标识
- ✅ 顶部显示错误提示："文件 test/test.md 已被移动或删除"

### 测试场景 2：选择"另存为"

**接上一个场景，点击"另存为"按钮**：

**步骤**：
1. 在弹出的对话框中点击"另存为"
2. 会弹出"新建 Markdown 文件"对话框
3. 文件名预填充为 `test.md`
4. 修改文件名为 `test-saved.md`
5. 点击"创建"

**预期结果**：
- ✅ 在文件树中出现新文件 `test/test-saved.md`
- ✅ 新文件包含之前编辑的所有内容
- ✅ 旧的 `test.md` 标签页自动关闭
- ✅ 新的 `test-saved.md` 标签页自动打开并激活
- ✅ 显示成功消息："创建成功"

### 测试场景 3：选择"关闭标签页"

**重复场景 1，但选择"关闭标签页"**：

**步骤**：
1. 重复场景 1 的步骤 1-8
2. 在弹出的对话框中点击"关闭标签页"

**预期结果**：
- ✅ 标签页 `test.md` 被关闭
- ✅ 编辑内容丢失（这是用户的选择）
- ✅ 如果有其他标签页，切换到下一个标签页
- ✅ 如果没有其他标签页，显示"打开本地 Markdown 文件"占位符

### 测试场景 4：文件被外部删除

**步骤**：
1. 在应用中打开文件 `test/test-renamed.md`
2. 编辑文件内容
3. 在 Windows 资源管理器中，删除 `test-renamed.md`
4. 返回应用，刷新文件树
5. 继续编辑，触发自动保存

**预期结果**：
- ✅ 行为与场景 1 相同
- ✅ 弹出"文件已被移动或删除"对话框
- ✅ 可以选择"另存为"保留内容

### 测试场景 5：文件被移动到其他文件夹

**步骤**：
1. 在应用中打开文件 `test/test.md`
2. 编辑文件内容
3. 在 Windows 资源管理器中，将 `test/test.md` 移动到根目录（`d:\project\NextTypora\test.md`）
4. 返回应用，刷新文件树
5. 继续编辑，触发自动保存

**预期结果**：
- ✅ 行为与场景 1 相同
- ✅ 弹出对话框
- ✅ 可以另存为或关闭标签页

## 修复总结

**问题根因**：前端 `openTabs` 持有旧路径，后端文件已移动，保存时返回 404。

**解决方案**：
1. 在 `useDebouncedSave` 中检测 404 错误
2. 触发 `onFileMissing` 回调
3. 标记标签页为 `missing: true`
4. 弹出对话框，提供恢复选项

**优势**：
- 用户不会丢失未保存的编辑内容
- 清晰的错误提示和恢复路径
- 不需要后端改动
- 最小化代码改动

**局限性**：
- 不会自动跟踪文件路径变化（需要 FileWatcher，复杂度高）
- 用户需要手动选择另存为的路径
- 只能在保存时检测到问题（不是实时检测）
