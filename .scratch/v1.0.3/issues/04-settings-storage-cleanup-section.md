# V103-04: 设置弹窗新增「存储」区块：清理旧备份目录

Status: resolved
Type: Change
Commit prefix: `Change V103-04:`
Spec section: 3（见 ../spec.md）

## 改动

递归扫描**当前工作区**，列出所有 `.nexttyproa-backups/`，显示「找到 N 个目录、共 X MB」，用户确认后整体移到系统回收站（复用 `file:trashItem`）。

三条约束：

1. 只扫当前工作区，不碰用户别的磁盘位置
2. 先报数再动手，用户看得见要删什么
3. 走回收站，可撤销

**不做首次启动自动弹窗**——升级后第一次打开就被质问「要不要删你的文件」，观感像流氓软件。

## 验收

扫描结果为 0 时按钮给出明确反馈而非静默；确认后目录进回收站而非永久删除。

## 完成情况（2026-11-01）

分层：**后端只报告，前端发起删除，Electron 走系统回收站**。后端一个字节都不删——这样"可撤销"这条约束由 `shell.trashItem` 保证，而不是靠后端自己小心。

### 后端

- `LegacyBackupService`：只扫当前工作区，递归找 `.nexttyproa-backups/`，报告每个目录的相对路径（正斜杠，可直接交给 `file:trashItem`）、文件数、字节数，以及总字节数。
- 遇到重解析点（junction / 符号链接）直接 `SKIP_SUBTREE`——它们可能指向工作区外，不跟进去也不报告。这一条和 V103-01 是同一个教训。
- 备份目录内部不再往下找嵌套的备份目录（整个目录会被一起移走，嵌套的字节数算在外层里）。
- 没有打开工作区时返回空结果而不是抛异常：设置面板里点"扫描"不该因此报错。
- `GET /api/maintenance/legacy-backups`，JavaBean DTO（跟 `dto` 包的既有风格一致，该包里没有 record）。

### 前端

设置弹窗新增「存储」区块，位置在「编辑器」和「图片上传」之间：

- 「扫描残留备份」→ 结果用 Alert 呈现：有残留时 warning 并逐个列出路径/文件数/体积，干净时 success 明说"当前工作区没有残留的备份目录"。
- 只有扫出东西时才出现「移到回收站」按钮。
- 删除逐个调 `window.nextTyproa.trashItem(path)`；没有这条通路时（非桌面环境）明确报错并且**什么都不做**。
- 部分失败会报出具体哪几个目录没成功；不论成败都重新扫描一次，让面板显示磁盘的真实情况而不是乐观假设。
- **没有首次启动自动弹窗**，按票要求。
