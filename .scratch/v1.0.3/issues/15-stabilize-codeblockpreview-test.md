# V103-15: CodeBlockPreview 的 Mermaid 异步用例在全量跑时超时

Status: resolved
Type: Bug
Commit prefix: `Fix Bug-V103-15:`
Spec section: 11（见 ../spec.md）

## 现象

`frontend/src/components/CodeBlockPreview.test.ts:48`「applies async previews for multiple Mermaid blocks independently」在全量跑时 5000ms 超时；**单独跑该文件 1.87 秒通过**。全量跑需 108 秒（import 阶段累计 172 秒）。

不是产品缺陷，是负载下的脆弱用例。但它证明了没有人跑过全量前端测试——否则这个会被看见。

## 改动

**改用例本身**（它等的是 Promise 链而非真实时间，用假定时器或显式 flush），不调高全局 `testTimeout`。

调高全局会让将来真正卡死的用例反馈更慢，而这是一个没有 CI 的项目最不该牺牲的东西。

## 验收

全量 `npm test` 连续跑三次都绿。

## Comments

## 调查结果（2026-11-01）

逐项测量后，原票里"它等的是 Promise 链而非真实时间，用假定时器或显式 flush"这个判断**是错的**。实测：

```
import=0ms  render=0ms  flush=1601ms  turns=2
```

时间全部花在让出事件循环上，每轮约 800ms，且**与等待方式无关**——换成 `vi.waitFor` 同样是 1.65 秒。同文件其余五条用例都是 0–4ms。

更强的复现（比 flaky 本身更干净）：把全局 `--testTimeout` 收紧。修复前即使空载单跑，1000ms / 300ms / 100ms 三档全部失败；而 5000ms 默认值能过。也就是说这条用例一直带着 1–5 秒的余量在跑，默认值只是刚好盖住它，并行负载下约 1/4 的全量跑会越界。

### 试过但没用的三种改法

1. 在用例体内先 `await import('mermaid')` 预解析模块 —— 无效（`import=0ms`，但 flush 仍 1.6 秒）。
2. 把等待从微任务推进（`await Promise.resolve()`）改为事件循环轮次 —— 无效，暴露出每轮约 800ms。
3. 在 `beforeAll` 里预热并抽干一次 mermaid 渲染路径 —— 无效，仍 1601ms / 2 轮。

**根因未查明。** 已知它不是模块解析缓存、不是等待机制、也不是前序用例遗留的在飞导入。

### 采用的改法

只消除 flaky，不假装修好了慢：

- 等待改为按调度轮次推进的 `flushUntil`，失败时给出真实的断言差异而不是 `waitFor` 超时（可读性净收益）。
- 给这一条**显式 30 秒超时**。它平时 1.6 秒结束，所以该值只在机器被压满时起作用；全局 `testTimeout` 仍为 5 秒，不牵连其余 189 条用例的反馈速度。
- 用例上方留了注释记录实测数字与"不要把这个超时搬到全局配置"的理由。

验证：以 `--testTimeout=1000`（修复前必失败）单跑该文件现在 6/6 通过，证明 per-test 超时生效且全局默认未被改动。

### 压力验证（2026-11-01）

| 条件 | CodeBlockPreview | 全量结果 |
| --- | --- | --- |
| 单套件 + 后端 `mvn test` 并发（历史上该用例失败的条件） | 通过 | 190/190 全过 |
| 两套件并发 + 后端并发（更恶劣） | 通过 | 挂 2 条，但挂的是 `MarkdownEditor.test.tsx`，见 V103-18 |
| 两套件并发 + 后端并发（重复一次） | 通过 | 同上，挂的是该组里另外 2 条 |

本用例在三次里**全部通过**，包含两次比历史失败条件更恶劣的。另有一条更强的确定性证据：以 `--testTimeout=1000` 单跑（修复前即使空载也必失败）现在 6/6 通过——因为 per-test 的 30 秒生效，而全局默认仍是 5 秒。预算从约 3 倍余量变成约 19 倍余量。

压力测试顺带挖出 V103-18：`MarkdownEditor` 的"保持原样"用例组在双套件并发下会丢模拟输入。与本票无关（未改动该文件），已单独立票。

### 遗留

那约 800ms 一轮的事件循环延迟没有解释，值得单独查（可能在 jsdom 环境或 vitest 模块运行器一侧）。它不影响正确性，只影响前端全量跑的总时长（现为约 108 秒）。建议作为 1.0.4 的独立调查项，不要再挂在本票下。
