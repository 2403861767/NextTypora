## 主题

起因是一条用户反馈：代码块右上角点「复制」成功后，界面上什么提示都没有。修好之后，顺着把编辑器和侧栏里用户看得到的英文都换成了中文；途中发现的两个斜杠菜单问题也一并修掉了。

这一版没有事先写 spec：各工单里都写着「1.0.4 主题未定，spec.md 待写」。这里的范围是发布时按实际完成的工单整理的。

## 发布验证（2026-11-07）

- `npm run dist:verify -- --expect-version 1.0.4`（exit 0）：Electron 30/30，后端 138/138，前端 235/235，构建通过，`test:packaged` 12/12，发布资源校验通过。
- `npm run dist:setup`：生成 `NextTypora-1.0.4-win-x64.exe`（169,841,873 字节），最后的 `verify:release` 通过。安装包自身的 PE 元数据和 `latest.yml`（大小、sha512）都对得上 1.0.4。
- 打包版冒烟测试：用同一次构建的 `release/win-unpacked/NextTypora.exe`、单独的 user-data-dir，通过命令行参数打开一篇临时笔记。CDP 负责输入和读 DOM，点进编辑器用真实的系统鼠标。12 项全部通过：
  - 主进程版本号和偏好设置「关于」里都是 1.0.4；
  - 侧栏是中文；代码块工具栏是「复制」「隐藏代码」；
  - 点「复制」弹出「已复制代码」，剪贴板里确实是代码（测试前备份了剪贴板，测完已还原）；
  - 图片块是中文；
  - 空段落里输入「、」变成 `/` 并弹出斜杠菜单，菜单分组和 16 个菜单项是中文，再输入「代码」只剩「代码块 Code」；
  - 菜单列表高度按窗口计算（视口 816 时 228px）；
  - 取消菜单后笔记文件不变；从标题栏按钮正常退出；
  - 真实的 `%APPDATA%\nexttyproa\settings.json` 前后 SHA-256 相同。

## 没有验证到的

- 真实中文输入法下按 `/`：没有切换这台机器的系统输入法实测。开发版里用 CDP 的 `Input.imeSetComposition` 走过 Chromium 的组字流程，见 V104-05。
- 安装程序本身：这次没有把安装包装进系统里测。冒烟测试跑的是同一次构建的 `win-unpacked`；安装器的脚本和 1.0.3 相同，这一版没有改动。
