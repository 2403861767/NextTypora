# V104-06: 窗口较矮时，斜杠菜单顶部被编辑区裁掉

Status: resolved
Type: Bug
Commit prefix: `Fix Bug-V104-06:`（和 V104-04、V104-05 合在一个提交里，见 V104-04）
Spec section: 无（2026-11-07 验收 V104-03 时在开发版里发现，尚无用户反馈）

## 现象

窗口较矮、光标在笔记中下部时输入 `/`，斜杠菜单翻到光标上方，但顶部被编辑区裁掉了。分组标签那一行（文本 / 列表 / 高级）完全看不见，第一个分组标题也贴着编辑区上沿。

V104-03 验收时实际出现过，截图在会话临时目录的 `v10403-check-menu.png`，没有放进仓库。当时的尺寸（CSS 像素）：

- 开发版 Electron 窗口，视口高 816，`devicePixelRatio` 1.25；
- 编辑区 `.typora-editor` 从 102 到 774，高 672；
- 菜单高 482：分组标签行约 61，加上 `.menu-groups` 的 `max-height: 420px`，再加内边距；
- 光标所在行约在 528：下方只有 774 − 528 = 246，上方只有 528 − 102 = 426，两边都放不下 482 + 10 的偏移。

同一个窗口里，光标在笔记靠上、或刚好让菜单能完整放在上方时，分组标签行是完整可见的（实测菜单顶 182 和 225 时都没被裁）。所以只在「上下都放不下」时才会出现。

这个问题和 V104-03 的汉化无关：菜单高度由 CSS 决定，跟文字长短无关，英文版本同样会被裁。

## 原因（从代码推断）

- 菜单定位：`@milkdown/plugin-slash` 的 `SlashProvider` 调用 floating-ui 的 `computePosition`，参数是 `placement: 'bottom-start'` 和 `middleware: [flip(), offset(10)]`（`slash-provider.ts:115-117`）。没有 `size` 或 `shift`，所以上下都放不下时，`flip` 只能挑一边，菜单不会缩短。
- 裁剪：菜单元素挂在 `view.dom.parentElement` 下，位于 `.typora-editor` 里面，而 `.typora-editor` 是 `overflow: auto`（`styles.css:1806`）。超出编辑区的部分就被裁掉了。
- Crepe 的 BlockEdit 配置只开放了块手柄（`blockHandle`）的 floating-ui 选项，**没有开放斜杠菜单 `SlashProvider` 的选项**（`root`、`middleware`、`floatingUIOptions`）。所以不能通过配置给它加 `size` 中间件，也不能把它挂到编辑区外面。

## 定案前要先弄清楚的

- 用户实际会用到多矮的窗口：多矮会触发，默认窗口尺寸会不会触发。打包版的默认窗口尺寸在 `electron/main.js`。
- 被裁掉时，滚动编辑区能不能把菜单顶部滚出来，还是菜单会随之关掉或错位。
- 可选修法和代价：
  - 只改 CSS：在 `styles.css` 里给 `.typora-editor .milkdown-slash-menu .menu-groups` 设一个随视口变化的 `max-height`（比如按 `vh` 算），让菜单在矮窗口里变短，上下总有一边放得下。不碰 Milkdown，但要确认菜单变短后键盘上下选择时，选中项还能滚到可见区域。
  - 给 Milkdown 打补丁，或者换成自己的 slash provider，加上 `size` / `shift` 中间件，或者把菜单挂到编辑区外面。代价明显更大。
- 测试方式：这是布局问题，jsdom 测不出来。参考 RW-P3 的做法，用 CSS 契约测试证明红→绿，再加真实浏览器里改动前后的几何测量。

### Triage（2026-11-07）

用户指示「这几个 ticket 全做完然后一起提交」，按下面的推荐定案。

查清的事实：

- **多矮会触发**：用 1440 宽、不同高度的视口，让光标停在编辑区每个高度（间隔 24px），各弹一次菜单。数字见完成情况的「修复前」：视口 1080 时只有编辑区最下方几行被裁；816 时中间约一半的行被裁；600 时全部被裁。打包版默认窗口是 1440×900（`electron/main.js:461`），开发版这个窗口的视口高 816，在会触发的范围内。
- **编辑区上下占掉的高度是固定的**：视口 600、700、816、1080 时，编辑区都是从 102 到 `视口高 - 42`，上下合计 144px，不随窗口变化。所以菜单高度可以按 `vh` 来算。
- **滚动编辑区能不能补救**：不用考察了。改完以后菜单在任何位置都完整显示（见完成情况）。

决定：

1. 只改 CSS：`.menu-groups` 的 `max-height` 改成 `clamp(120px, calc(50vh - 180px), 420px)`。推导：菜单 = 列表 + 62px（分组标签行加边框），加 10px 偏移和一行光标（按 32px 算），不超过编辑区（`100vh - 144px`）的一半，留 20px 余量。最少 120px，还能看到两三项；最多仍是 Crepe 的 420px，高窗口里和原来一样。
2. 选择器写成 `.typora-editor .milkdown .milkdown-slash-menu .menu-groups`，比 Crepe 的 `.milkdown .milkdown-slash-menu .menu-groups` 多一个类，不依赖样式表的加载顺序。
3. 不给 Milkdown 打补丁，也不换成自己的 slash provider：CSS 已经能完整解决，后两种代价大得多。
